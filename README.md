# OrgSolvency

**Проверка исполнимости обязательств организации по её собственным документам.**

Трек: ИИ-агент «Анализ организационной структуры и функционала» · Команда: **Artifex**

```bash
python3 webapp/server.py                   # интерфейс: загрузка и заключение
python3 run.py                             # то же в консоли, на контрольном корпусе
python3 run.py before.docx after.docx      # прогон на документах заказчика
python3 tests/smoke.py                     # рубеж полноты и дословности цитат
python3 tests/ai_seam.py                   # разъём модели работает без ключа и сети
```

Ни сборки, ни npm, ни зависимостей: страница отдаётся одним файлом, движок
вызывается напрямую.

Зависимостей нет — только стандартная библиотека Python 3. Открыть `out/report.html`.

---

## Идея

Внутренние документы компании — это набор обязательств: перед регулятором, перед
Советом директоров, перед самой собой. Реорганизация часть этих обязательств молча
ломает. Выясняется это на внешнем аудите, через год.

Продукт отвечает на один вопрос:

> **После реорганизации осталось ли в компании обязательство, которое теперь
> некому исполнить?**

Это не сравнение документов. Это **проверка организации на исполнимость** —
сравнение редакций оказывается лишь частным случаем.

### Почему не диффом

Смотрите, какие выводы на контрольном комплекте оказались важными:

| Вывод | Почему диффом не берётся |
|---|---|
| п. 5.6.3 исчез, но п. 11.2 через шестьдесят страниц всё ещё требует эту работу | обязательство и полномочие — в разных главах, между ними нет текстового сходства |
| функция выдана в главе 2 и запрещена в главе 5 | обе нормы в **одном** документе, сравнивать не с чем |
| ДККМ оценивает качество аудита, подчиняясь тому, кого оценивает | нужно понимать, что такое независимость |

Диффом берётся только то, что и так видно глазами.

### Модель

Документы разбираются на нормы трёх видов:

- **обязательства** — что должно происходить (с уровнем обязательности и периодичностью);
- **полномочия** — что конкретное подразделение вправе делать;
- **запреты** — что делать нельзя.

Обязательство **исполнимо**, если существует цепочка: обязательство → покрывающее
его полномочие → живое подразделение-владелец → отсутствие запрета на это действие.
Отклонения — это разорванные цепочки.

| Класс | Разрыв цепочки |
|---|---|
| `orphan` | обязательство действует, полномочия его исполнить нет ни у кого |
| `lost` | полномочие было, владелец сохранился, полномочия больше нет |
| `transferred` | полномочие нашлось у другого владельца — **не** потеря |
| `weakened` | норма выжила текстом и ослабла как обязательство |
| `duplicated` | одно полномочие у двух владельцев, не связанных подчинением |
| `collision` | полномочие описывает действие, прямо запрещённое тем же документом |
| `conflict_of_interest` | оценивающий и оцениваемый совпадают |
| `broken_reference` | ссылка пережила перенумерацию и указывает на другую норму |

Решётка обязательности: `обязан > должен > осуществляется > может > вправе`.
Снижение по ней — отдельный класс вывода, а не редакторская правка.

## Интерфейс

Экран загрузки принимает два комплекта — «до» и «после», .docx или текст.
Результат — итоговое аналитическое заключение (must-have №5) и перечень
отклонений, где **каждый вывод раскрывается в цепочку получения и подтверждающие
цитаты** (must-have №4).

Клик по цитате открывает исходный документ с подсвеченным фрагментом: от вывода
до буквы исходного текста — два движения мыши.

## Прослеживаемость

Цитата не формулируется моделью, а **вырезается из файла по символьным смещениям**.
Перед публикацией каждая цитата проверяется на дословное вхождение в исходный текст
обычным поиском подстроки (`orgsolvency/verify.py`) — не модель проверяет модель.
Ссылка на несуществующий пункт структурно невозможна.

Каждый вывод несёт цепочку получения (`trace`), а не только вердикт:

```
Обязательство п. 11.2 действует, но ни одно подразделение
не наделено полномочием его исполнить
  1. обязательность: уровень 3
  2. ни одна функция с владельцем не покрывает предмет (порог 0.20)
  3. исполнимость обязательства не обеспечена структурой
```

## Замеренный результат

Детерминированный слой, **без единого обращения к модели**:

```
пунктов разобрано: 38 «до» / 37 «после»
отклонений: 18
ЗОЛОТОЙ НАБОР: 10/21 найдено   recall = 48%
негативные тесты пройдены: ложных срабатываний на контрпримерах нет
```

Подробности и разбор непойманного — [`BENCHMARK.md`](BENCHMARK.md).

Половина — это пол, а не потолок. Ценность числа в том, что видно, **какая именно**
половина не берётся лексикой и почему именно там нужна модель.

## Где в системе модель

Разъём готов и проверен тестом: `orgsolvency/ai.py`.

```bash
export ARTIFEX_AI=anthropic          # либо openai
export ARTIFEX_AI_KEY=sk-...
export ARTIFEX_AI_MODEL=claude-sonnet-5
python3 webapp/server.py
```

Без переменных окружения работает лексический слой — это штатный режим, а не
деградация. В шапке интерфейса видно, какой движок отвечает, а у каждого
вывода, решённого моделью, стоит отметка «решено моделью».

Три условия, которые слой обязан сохранять и которые закреплены тестом:

* **модель зовут только в полосе неопределённости** `0.18 ≤ сходство < 0.45`.
  Выше — совпадение и так очевидно, ниже — заведомо разные нормы. На контрольном
  комплекте это пять обращений вместо семисот попарных сравнений;
* **вердикты кэшируются по хэшу пары** — повторный прогон даёт тот же результат;
* **модель не формирует номера пунктов и цитаты.** Она отвечает ровно на один
  вопрос: «одна ли это функция». Цитата уже вырезана из файла, поэтому выдуманная
  ссылка невозможна даже при полной галлюцинации.

Отказ сети не роняет прогон: провайдер возвращает «не берусь судить», и остаётся
лексический слой.

Места, где модель даёт прибавку — там, где лексика провалилась на замере:

1. **Покрытие обязательства полномочием.** «Внешняя оценка проводится» ↔ «предложения
   по объёму внешней оценки» — связь смысловая, не словарная.
2. **Тождество функций при разной формулировке.** `L3`, `L6`: полномочие не исчезло,
   а переписано другими словами, и лексика считает это потерей.
3. **Коллизия с запретом.** `C1`: «содействие в разработке процедур» против «участвовать
   в реализации процессов». Ни одного общего значимого слова.
4. **Агент-следователь.** Не конвейер, а цикл: «п. 11.2 требует внешнюю оценку — кто
   вправе её организовать? → поиск → никто → подразумевается ли в другом месте? →
   поиск → нет → вывод». Следующий шаг выбирается по результату предыдущего.

Модель рассуждает свободно и стремится к полноте. Контроль дословности цитат не
ограничивает рассуждение — он лишь делает невозможным вымышленный номер пункта.
Детерминированный слой при этом никуда не девается: он остаётся полом, на который
система садится, если слой модели откажет на защите.

## Состав

```
corpus/          выдержка из контрольных документов (дословно, с номерами пунктов)
golden/          золотой набор: 22 размеченных отклонения + негативные тесты
orgsolvency/
  ingest.py      .docx без зависимостей; помечает пункты без надёжного якоря
  core.py        текст → пункты → нормы (модальность, владелец, ссылки)
  detect.py      детекторы разорванных цепочек
  verify.py      контроль дословности цитат
  ai.py          разъём слоя модели: полоса неопределённости, кэш, отказоустойчивость
  summary.py     итоговое заключение на человеческом языке
  report.py      HTML-заключение и машинный вывод
  score.py       метрика против золотого набора
docs/            ручной разбор контрольного комплекта
webapp/          интерфейс: сервер на стандартной библиотеке + одна страница
tests/           рубеж полноты, дословности цитат и живости разъёма модели
run.py           точка входа
```

## Разделение работ

| | Зона |
|---|---|
| A | форматы: .docx готов, дальше pdf/xlsx и таблицы внутри документов |
| B | слой модели: разъём готов — включить провайдера, поднять метрику, агент-следователь |
| C | интерфейс готов; дальше экспорт заключения, сравнение по подразделениям |

Сквозной прогон уже работает — новые слои подключаются к живому конвейеру,
а не интегрируются в последний час.
