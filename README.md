# OrgDiff — AI-агент анализа организационной структуры и функционала

Трек: **ИИ-агент «Анализ организационной структуры и функционала»**
Команда: **Artifex**

Агент сравнивает комплекты организационных документов «до» и «после» реорганизации и
находит **потерю функций, дублирование функционала, конфликт интересов и нормативные
коллизии** — каждый вывод с прямой ссылкой на пункт документа.

---

## Принцип: ИИ читает, код решает

Наивный подход — положить два документа в контекст модели и спросить «что изменилось».
Ответ выглядит убедительно, частично выдуман, и при повторном запуске будет другим.
Для внутреннего аудита это неприменимо.

Наш конвейер разделяет восприятие и суждение:

| Слой | Кто выполняет | Свойство |
|---|---|---|
| Извлечение фактов из пунктов | LLM (строгая JSON-схема) | воспроизводимо через кэш по хэшу пункта |
| Сопоставление формулировок | эмбеддинги + LLM-арбитраж кандидатов | решение фиксируется с confidence |
| Поиск отклонений | детерминированный код (правила над графом) | один и тот же результат при каждом запуске |
| Проверка вывода | агент-фальсификатор + grounding-гейт | вывод без подтверждения не публикуется |

Следствие: каждый вывод имеет **цепочку обоснования** и **ссылку на источник**,
а прогон полностью воспроизводим.

## Единица анализа — функциональный атом

Не «чанк текста», а запись:

```
(субъект, предикат, объект, модальность, квалификатор) → (документ, пункт, символьный диапазон)
```

Пример из тестовых данных:

```
ДККМ | вносить предложения | объём и содержание внешней оценки БВА | право | ред.8 §5.6.3
```

Нумерация пунктов в исходных документах (`5.3.4б`, `2.3.1ж`) используется как
естественный идентификатор и якорь цитирования — это даёт прослеживаемость
структурно, а не «по обещанию модели».

## Классы отклонений

| Класс | Определение |
|---|---|
| `lost` | атом есть в «до», владелец сохранён/имеет преемника, в «после» соответствия нет |
| `transferred` | атом есть в «после», но у другого владельца (проверяется **раньше** `lost`) |
| `weakened` | модальность понизилась: `обязан > должен > осуществляется > может > вправе`; либо снята периодичность |
| `duplicated` | одна каноническая функция у двух подразделений без связи `reports_to` между ними (вертикальный каскад ≠ горизонтальное дублирование) |
| `orphan` | функция объявлена в разделе целей/задач, но не закреплена ни за одним подразделением |
| `collision` | закреплённая функция пересекается с прямым запретом в том же документе |
| `conflict_of_interest` | матрица несовместимости: исполняет ∧ контролирует, оценивает собственного руководителя, инициирует ∧ утверждает |
| `broken_reference` | перекрёстная ссылка указывает на пункт, сменивший смысл после перенумерации |

## Разделение работ

| | Зона | Стартует на |
|---|---|---|
| A | файлы → дерево пунктов → атомы (docx/pdf/xlsx, смещения, устойчивость к битой разметке) | реальных документах |
| B | сопоставление + правила + фальсификатор + бенчмарк | фикстурах `fixtures/` |
| C | API, UI, Docker, README, демо | фикстурах `fixtures/` |

Контракт (`schemas/`) и золотой набор (`golden/`) фиксируются **до** написания кода —
это то, что позволяет трём людям работать параллельно, а не в очереди.
Сквозной прогон обязателен на 40% бюджета времени, даже в черновом виде.
