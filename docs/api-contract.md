# Контракт между движком и интерфейсом

Движок и интерфейс пишутся параллельно. Этот файл — граница между ними.
Интерфейс достраивает недостающее сам (`normalize()` в `webapp/index.html`),
поэтому неполный ответ не ломает экран — но чем полнее ответ, тем меньше
интерфейс додумывает.

## Что отдаёт `POST /api/analyze` и `GET /api/demo`

```jsonc
{
  "summary": {
    "headline":  "Реорганизация оставила 3 обязательства без исполнителя",
    "narrative": ["...", "..."],          // до трёх утверждений, показываются все
    "kpi":       [{"value": 18, "label": "отклонений", "tone": "default|ok|critical|muted"}],
    "by_consequence": [                    // порядок групп на экране
      {"key": "not_done", "label": "Функция не исполняется",
       "hint": "одна строка: почему это важно", "count": 7, "proven": 0}
    ],
    "identical": false                     // комплекты совпадают — необязательно
  },
  "findings": [ /* см. ниже */ ],
  "documents": {
    "before": {"doc_id": "before", "title": "...", "text": "полный текст",
               "files": ["a.docx"], "clauses": 38, "numbered": 38, "collisions": 0},
    "after":  { "...": "то же" }
  },
  "structure": {                         // must-have №1: подразделения до и после
    "before": [{"id": "DKKM", "name": "...", "abbrev": "ДККМ", "side": "before",
                "status": "preserved|transformed|created|abolished",
                "positions": ["..."], "functions": 7, "clauses": ["5.5.3"]}],
    "after":  [ /* то же */ ],
    "links":  [{"from": "DKKM", "to": "DKKM", "status": "transformed",
                "score": 1.0, "why": ["совпадает аббревиатура ДККМ", "общий функционал 0.55"]}]
  },
  "unit_counts": {"preserved": 1, "transformed": 1, "created": 2, "abolished": 1},
  "engine":  {"engine": "правила | правила + модель", "available": false, "model": null},
  "timings": [{"name": "Сопоставление функций", "ms": 69}],
  "total_ms": 69,
  "rejected": 0                            // цитат отклонено контролем дословности
}
```

## Вывод (`findings[]`)

| Поле | Обязательно | Назначение |
|---|---|---|
| `statement` | да | одно предложение, которое читает пользователь |
| `type` | да | `orphan · lost · transferred · weakened · duplicated · collision · conflict_of_interest · broken_reference · unit_created · unit_abolished · unit_transformed` |
| `evidence[]` | **да, минимум одна** | вывод без источника интерфейс не показывает вовсе |
| `rule_id` | желательно | показывается рядом с цепочкой вывода |
| `trace[]` | желательно | нумерованная цепочка «как получен вывод» |
| `engine` | желательно | `"правила"` или `"модель"` — ставит отметку «решено моделью» |
| `consequence`, `consequence_label` | нет | выводится из `type`, если не прислать |
| `certainty` | нет | выводится из `type` и `engine` |
| `recommendation` | нет | строка «Что делать» |
| `confidence` | нет | число 0..1 |

### `evidence[]`

```jsonc
{"doc_id": "before|after", "clause": "5.6.3", "quote": "дословный текст пункта",
 "span": [48210, 48312], "role": "before|after|prohibition|requirement|
                                   reference_source|reference_target",
 "file": "Положение.docx"}
```

`span` — символьные смещения в `documents[doc_id].text`. Если смещения не
совпадут с `quote`, интерфейс найдёт цитату поиском подстроки, но подсветка
будет менее точной при повторах текста.

`file` нужен, когда в комплекте несколько документов: «п. 5.1» есть в каждом,
и ссылка без имени файла перестаёт быть однозначной.

## Три правила, которые движок обязан соблюдать

1. **Цитата вырезается из файла, а не формулируется.** `quote` должна дословно
   входить в `documents[doc_id].text`; `orgsolvency/verify.py` это проверяет и
   отбрасывает вывод, если не входит.
2. **Отсутствие не доказывается цитатой.** Выводы `orphan` и `lost` утверждают,
   что чего-то нет. Интерфейс помечает их «требует проверки» независимо от
   `confidence` — не переопределяйте это полем `certainty`, если не появилось
   настоящего доказательства.
3. **Модель не формирует номера пунктов.** Она отвечает на вопрос «одна ли это
   функция», и её участие отмечается `engine: "модель"`.

## Ошибки

```jsonc
{"error": "Текст на русском, который можно показать пользователю"}
```

`400` — ошибка входных данных (пустой файл, не .docx, нет нумерации).
`500` — внутренняя ошибка; трассировка уходит в консоль сервера, а пользователь
видит общую фразу. Никогда не возвращайте `str(exc)` напрямую.

## Чего в контракте ещё нет

Все пять must-have закрыты. Незакрытым остаётся слой модели: разъём готов
(`orgsolvency/ai.py`), провайдер подключается переменными окружения, и
двенадцать пропусков из `BENCHMARK.md` ждут именно его.
